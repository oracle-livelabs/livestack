# Terraform Provisioning Notes

This stack supports two different phases:

1. Build a reusable base image manually with `inst.sh`.
2. Launch that image through Terraform so Terraform provides the real ADB, wallet, password, and OCI API-key metadata.

The important rule is that the manual image-build phase must not try to create the `PG` DBMS_CLOUD_AI profile with placeholder API-key values. The Terraform phase should create the profile after `PG` is seeded, because Terraform provides the correct fingerprint, private key, tenancy OCID, user OCID, compartment OCID, and GenAI region.

## What Terraform Provides

The active Terraform configuration in:

```text
/Users/klazarz/Documents/GitHub/livelabs/terraform/ds-jup-ai-plat-dev
```

creates the ADB and compute instance, then passes deployment values into OCI instance metadata. The relevant values are:

- `dbpassword`: generated by `random_string.password.result`
- `pem_key`: generated OCI API private key material
- `pem_key_fingerprint`: uploaded OCI API key fingerprint
- `user_ocid`
- `tenancy_ocid`
- `compartment_ocid`
- `ai_endpoint_region`
- `oci_auth_type=api_key`
- `oci_genai_model=cohere.command-a-03-2025`
- `oci_ai_profile_name=PG_GENAI_PROFILE`
- `oci_genai_credential_name=PG_OCI_GENAI_CRED`
- `gravitino_jdbc_user=PG`
- `gravitino_object_storage_bucket`
- `gravitino_object_storage_prefix=iceberg`
- `gravitino_s3_endpoint`
- `gravitino_s3_region`
- `gravitino_s3_access_key_id`
- `gravitino_s3_secret_access_key`

On boot, `/home/opc/init/setenv.sh` writes these values into `/home/opc/ingestion/.env`. The app container reads that file through Podman Compose.

## How ADB Is Bootstrapped

The host boot process owns the first ADB bootstrap. Terraform does not create `PG`, because `PG` is created by the LiveStack bootstrap using the same generated `dbpassword` that is passed into the app stack.

The startup order is:

1. `/home/opc/init/setenv.sh` writes Terraform metadata into `/home/opc/ingestion/.env`.
2. `adb-wallet.service` downloads and unpacks the ADB wallet once.
3. `adb-load.sh` runs SQLcl on the host once, before Podman Compose starts. It is invoked after the wallet download and is also available as `adb-load.service` for intentional reruns.
4. `user-podman.service` starts the compose stack.
5. `pg-iceberg-connection.service` updates the platform-created Data Transforms
   Oracle connection to use `PG` with the current `dbpassword`, verifies `PG`
   as its default schema, creates or updates the Apache Iceberg connection named
   `pg-iceberg` with REST URL `http://<public-ip>:1525/iceberg`, and verifies
   both connections through the Data Transforms agent.

`adb-load.service` runs `/home/opc/init/adb-load.sh`. The script connects to ADB with SQLcl, recreates the `PG` user, creates the Bronze and Silver objects, creates the application schema objects, loads the warehouse CSV exports from `/home/opc/ingestion/gold-data`, loads the app seed data, and verifies that all required demo tables contain rows.

On success it writes:

```text
/home/opc/ingestion/.adb_load_done
```

That marker prevents the ADB data load from running again after a reboot.

## How The PG AI Profile Is Created

After the SQLcl bootstrap creates `PG` and loads the Bronze, Silver, and Gold objects, the same host bootstrap attempts to create the PG DBMS_CLOUD_AI profile when profile setup is enabled:

1. Grants `PG` access to `DBMS_CLOUD` and `DBMS_CLOUD_AI`.
2. Creates a `PG` DBMS_CLOUD credential named `PG_OCI_GENAI_CRED`.
3. Creates an enabled DBMS_CLOUD_AI profile named `PG_GENAI_PROFILE`.
4. Uses OCI API-key authentication.
5. Uses model `cohere.command-a-03-2025`.
6. Exposes all `PG` objects with:

```json
[{ "owner": "PG" }]
```

The setup is controlled by:

```bash
PG_AI_PROFILE_AUTO_SETUP=true
```

If the flag is missing, Compose defaults it to `true`.

The app still checks and reports the profile status on startup. If the host SQLcl profile setup is skipped or cannot complete, the app can still reconcile the profile when the required Terraform-provided API-key values are available.

## Network Requirement For Data Transforms Iceberg

`pg-iceberg-connection.service` verifies the connection from ADB Data
Transforms to the VM. The public subnet or network security list used by
`var.ociPublicSubnetOcid` must allow inbound TCP `1525` to the instance, in
addition to the host firewall rule configured by `inst.sh`.

## Manual Base Image Build

When building the base image manually with `inst.sh`, Terraform metadata is not available yet. If the server has placeholder or old hardcoded OCI API-key values, profile creation can fail or create a profile that only fails when used.

For the manual build run, disable profile setup:

```bash
cd /home/opc/ingestion
grep -q '^PG_AI_PROFILE_AUTO_SETUP=' .env \
  && sed -i 's/^PG_AI_PROFILE_AUTO_SETUP=.*/PG_AI_PROFILE_AUTO_SETUP=false/' .env \
  || sed -i '1iPG_AI_PROFILE_AUTO_SETUP=false' .env
```

Restart the stack if it is already running:

```bash
systemctl --user restart user-podman.service
```

## Do Not Bake Build Credentials

`.env.kev` is a local build-input file. It is ignored by Git and excluded from
`build_dev.zip`, but its contents become `/home/opc/.env` during a manual build
and are expanded into `/home/opc/ingestion/.env`, OCI key files, container
configuration, and named volumes when the stack starts. Never capture the image
before running `prepare-custom-image.sh`.

For a Marketplace image, use disposable build credentials and revoke or rotate
the database password, OCI API key, Object Storage customer secret key, wallet,
and PAR URLs after the build. Removing files prevents normal reuse from a
launched image, but deletion from a cloud block volume is not a substitute for
credential rotation.

## Before Creating The Custom Image

Before taking the custom image, stop the user services and run the cleanup script as the final action on the build VM:

```bash
systemctl --user stop pg-iceberg-connection.service iceberg-seed.service user-podman.service adb-load.service adb-wallet.service
cd /home/opc
./prepare-custom-image.sh
```

The script:

- verifies every rendered Compose image, the prebuilt Iceberg seeder, the
  configured Ollama model, and the OracleDB, Vite, and KafkaJS dependency caches
  before deleting anything
- runs `podman-compose down --remove-orphans`, then uses the
  `io.podman.compose.project` label to remove sensitive runtime volumes and
  attached anonymous volumes
- retains the built images, staged installer archives, and only the
  `ingestion_ollama-models`, `ingestion_app-node-modules`,
  `ingestion_frontend-node-modules`, and
  `ingestion_signal-generator-node-modules` volumes for offline first boot
- clears every generated file under `/home/opc/ingestion/wallet`
- removes `/home/opc/ingestion/.adb_load_done`
- creates `/home/opc/ingestion/.oci_wallet_required` so metadata outages cannot re-enable fallback
- deletes only ZIPs whose contents identify them as ADB wallets, including the configured path under `/home/opc`
- removes `/home/opc/.env` and `/home/opc/ingestion/.env`
- removes `/home/opc/inst.log` and generated application logs, which can contain
  build PAR URLs or environment-specific diagnostics
- removes persistent Podman and Docker-compatible registry authentication files
- removes generated OCI API-key files under `/home/opc/.oci` and `/home/opc/ingestion/.oci`
- removes the generated GoldenGate TLS private key so each provisioned VM creates its own key

Verify the image is clean:

```bash
test -z "$(find /home/opc/ingestion/wallet -mindepth 1 -print -quit)"
test ! -e /home/opc/ingestion/.adb_load_done
test -e /home/opc/ingestion/.oci_wallet_required
test ! -e /home/opc/.env
test ! -e /home/opc/inst.log
test ! -e /home/opc/ingestion/.env
test ! -e /home/opc/.oci
test ! -e /home/opc/ingestion/.oci
test ! -e /home/opc/.config/containers/auth.json
test ! -e /home/opc/.docker/config.json
test ! -e /home/opc/ingestion/cdc/goldengate/cert
test ! -e /home/opc/ingestion/logs
podman image exists localhost/iceberg-seeder:latest
test -z "$(podman ps --all --filter label=io.podman.compose.project=ingestion -q)"
podman volume exists ingestion_ollama-models
podman volume exists ingestion_app-node-modules
podman volume exists ingestion_frontend-node-modules
podman volume exists ingestion_signal-generator-node-modules
podman volume ls --filter label=io.podman.compose.project=ingestion --format '{{.Name}}' | sort
```

The final command must show exactly the four offline dependency volumes listed
above. No project containers or runtime volumes should remain. Do not restart
the build VM services after cleanup. Stop the VM and create the custom image.
The Terraform-created instance will rebuild its runtime environment from OCI
metadata, generate a wallet for its provisioned ADB, recreate sensitive runtime
volumes, and rerun the SQLcl bootstrap while reusing the baked images and
dependency caches. If OCI wallet generation fails, first boot fails without
installing a static wallet from the image.

## Terraform Deployment Validation

After launching the custom image through Terraform, validate in this order:

```bash
ssh opc@<public-ip>
systemctl --user status user-podman.service
systemctl --user status adb-load.service
systemctl --user status pg-iceberg-connection.service
ls -la /home/opc/ingestion/wallet
ls -la /home/opc/ingestion/.adb_load_done
grep -E '^(PG_AI_PROFILE_AUTO_SETUP|OCI_AUTH_TYPE|OCI_GENAI_MODEL|OCI_AI_PROFILE_NAME|OCI_GENAI_CREDENTIAL_NAME)=' /home/opc/ingestion/.env
grep -E '^(GRAVITINO_JDBC_USER|GRAVITINO_OBJECT_STORAGE_BUCKET|GRAVITINO_OBJECT_STORAGE_PREFIX|GRAVITINO_S3_ENDPOINT|GRAVITINO_S3_REGION|GRAVITINO_S3_ACCESS_KEY_ID)=' /home/opc/ingestion/.env
grep -E '^(DATA_TRANSFORMS_ICEBERG_CONNECTION_NAME|DATA_TRANSFORMS_ICEBERG_REST_URL|DATA_TRANSFORMS_BASE_URL)=' /home/opc/ingestion/.env || true
```

Expected values:

```bash
OCI_AUTH_TYPE=api_key
OCI_GENAI_MODEL=cohere.command-a-03-2025
OCI_AI_PROFILE_NAME=PG_GENAI_PROFILE
OCI_GENAI_CREDENTIAL_NAME=PG_OCI_GENAI_CRED
GRAVITINO_JDBC_USER=PG
GRAVITINO_OBJECT_STORAGE_PREFIX=iceberg
DATA_TRANSFORMS_ICEBERG_CONNECTION_NAME=pg-iceberg
```

`PG_AI_PROFILE_AUTO_SETUP` may be absent. If absent, it defaults to `true`.
`DATA_TRANSFORMS_ICEBERG_REST_URL` and `DATA_TRANSFORMS_BASE_URL` may be
absent when they can be derived from the VM public IP and ADB metadata.

Then check the app status:

```bash
curl -s http://localhost:8505/api/demo/status
```

The lakehouse status should show the server ADB connection, `goldDataLoaded: true`, and an `aiProfile` object once the profile has been created.

## Troubleshooting

If the profile is not created:

1. Check `/home/opc/ingestion/.env` for `PG_AI_PROFILE_AUTO_SETUP=false`.
2. If present on a Terraform-created instance, remove it and restart:

```bash
sed -i '/^PG_AI_PROFILE_AUTO_SETUP=/d' /home/opc/ingestion/.env
systemctl --user restart user-podman.service
```

3. Check that the generated OCI values are present:

```bash
grep -E '^(OCI_USER_OCID|OCI_TENANCY_OCID|OCI_COMPARTMENT_ID|OCI_FINGERPRINT|OCI_PRIVATE_KEY|OCI_REGION)=' /home/opc/ingestion/.env
```

4. If the wallet does not refresh for the Terraform ADB, remove the wallet marker and restart the wallet service:

```bash
rm -f /home/opc/ingestion/wallet/.wallet_done
systemctl --user restart adb-wallet.service
systemctl --user restart user-podman.service
```

5. If the ADB data was not loaded, check the SQLcl bootstrap log:

```bash
tail -200 /home/opc/ingestion/logs/adb-load.log
systemctl --user status adb-load.service
```

To rerun the SQLcl ADB bootstrap intentionally:

```bash
rm -f /home/opc/ingestion/.adb_load_done
systemctl --user restart adb-load.service
systemctl --user restart user-podman.service
```
