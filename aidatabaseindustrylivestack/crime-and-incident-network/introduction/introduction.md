# IncidentData LiveStack workshop

## Introduction

Follow a synthetic payment-document comparison in the active city profile. Start with the signed-in scope, examine a watch and its source records, compare search and graph views, and finish with the two Ask and agent routes plus the Data Room pipeline. The 2 November deployment check used Perth; an instructor can prepare another city before the session.

Estimated Workshop Time: 133 minutes (about 2 hours 15 minutes), excluding optional OCI deployment.

![Conceptual IncidentData learning journey](../images/incidentdata-overview.png)

### Objectives

- Explain what the selected city and demo persona allow you to see.
- Distinguish original incidents, contextual signals, vector comparisons, recorded links and AI drafts.
- Compare the guided handler routes with the configured Select AI and agent framework routes.
- Trace a synthetic ZIP through the seven Data Room stages.

## Before you begin

1. Open **application_url** from the successful Resource Manager Apply job, or use the instructor-assigned URL. To retrieve your own operator login, open **application_credentials_url** while signed into OCI and download the object named by **application_credentials_file**. Keep this private JSON file private.
2. Sign in with the assigned application account. **operator** has **Statewide administrator** scope. Resource Manager binds scope to the login, so **Signed-in scope** is disabled. Record the active city and profile in **Data Foundation**; the verified default was Perth (**PERTH_DATA_V2**). Do not restore Adelaide merely to match an example. A restore changes shared data and belongs to instructor preparation.
3. Keep a second browser tab for this guide. Application counts, available cases, vectors, evidence and saved batches depend on the active profile, persona and preparation state. Read what your session actually shows.
4. Use only synthetic training material. For an optional scope comparison, use an instructor-assigned participant account in a separate browser profile or private session. A second tab can reuse the operator's HTTP Basic login. Only a separate local demo may offer an enabled **Demo user** selector. Do not share the operator login or use this application for operational policing decisions.
